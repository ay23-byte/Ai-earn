# Requirements and traceability

Status values here are `VERIFIED`, `NOT_IMPLEMENTED`, or `UNVERIFIED`; phase statuses are tracked separately. These are grouped requirements, not permission to omit the detailed acceptance criteria in the original project brief. A grouped row covers all its listed subrequirements. The Phase 1 offline foundation exists; earning and security workflows do not. Where a test is marked pending, no automated test has been claimed. Locations for later-phase rows remain unassigned. The unresolved dependency on prerequisite phases applies to every later row, in addition to the specific dependencies listed.

## Change control

Expand rows into narrower stable IDs when implementation needs more detail, preserving the parent IDs and original acceptance criteria. Update implementation paths and exact tests as each phase progresses. Security, financial, user-data and external-commitment requirements must not be weakened without user approval. No proposed feature should be represented as implemented because it appears in this matrix.
